# Codex companion agent routing

This directory is the **Codex desktop / CLI variant** of the OpenCode Go Mod project. Its package is `codex-companion/plugin.json` plus `mcp.json`, `skills/`, `shared/` and `server/`. The canonical shared provider modules live in the repository's `bridge-core/`; `scripts/sync-codex-shared.mjs` generates the package-local copies, and CI checks that they match. The MCP manifest points to the bundled `server/dist/index.mjs`: after changing server/shared sources, run `npm run build`, then `npm run check` to verify the checked-in bundle and tests. `npm run check` does not regenerate the bundle. The **Claude Code variant is at the repository root** (`.claude-plugin/`, `hooks/`); it is **not** installed here.

When a user asks you to install this mod for Codex, install THIS package; when a user asks for Claude Code, go back to the repository root and follow the Claude installer, even if you are a Codex agent. Read `../docs/INSTALLATION.md` before installation. Codex uses this package's MCP, skill and optional loopback dashboard; it does not load Claude's sidebar API. The integration is in draft [PR #5](https://github.com/abharrison1995-droid/opencode-go-mod/pull/5); Actions run [#41198897383](https://github.com/abharrison1995-droid/opencode-go-mod/actions/runs/41198897383) passed on revision `277ff3a`. Codex Desktop discovery is unverified; Codex Pro profiles are not set up, OpenCode CLI lacks the usage API command, and Antigravity returned connected details without structured quota. See `../docs/INTEGRATION-AUDIT.md` for exact live results. Pass an absolute active workspace `directory` to `bridge_usage` for OpenCode; without it, OpenCode is reported unavailable. Verify plugin discovery and a read-only MCP call before declaring host installation successful. For edits, `start_pipeline_job` requires `BRIDGE_ENABLE_WRITES=1`, uses a preserved isolated worktree and never merges or pushes. The verifier gets an environment allowlist but is not OS-sandboxed; test code retains the current user's filesystem permissions. The maximum concurrent job count is eight.
