This is a separate Codex-native plugin package in the same repository as the Claude mod. It uses a local MCP server and a Codex skill, not the Claude-only UI hooks.

Supported MCP tools: `bridge_status`, `bridge_usage`, `bridge_history`, `delegate_agent`, `start_agent_job`, `get_agent_job`, `cancel_agent_job` and `start_pipeline_job`. Delegation supports OpenCode, Codex CLI, Claude Code and Antigravity, with explicit provider selection and optional model/reasoning selection. A single explicit cross-provider fallback can be configured for missing CLI, authentication or rate-limit failures. Codex-to-Codex profile rotation is rejected. Codex calls require `pro-1` or `pro-2` and use separate `CODEX_HOME` directories. All workers default to read-only. Editing requires both `allowWrites=true` and the owner-set `BRIDGE_ENABLE_WRITES=1` environment variable; Antigravity editing remains disabled in this companion.

Existing Z.AI Coding Plan models remain available through OpenCode when selected by model ID (such as `zai-coding-plan/...`). The shared quota engine has no dedicated Z.AI telemetry adapter, so Z.AI allowance is not shown as server-reported usage.

The shared telemetry engine reads OpenCode's documented local usage API, Codex app-server `account/read` and `account/rateLimits/read` for both isolated profiles, and Antigravity's read-only `/usage` command. Pass an absolute `directory` to `bridge_usage` for OpenCode's workspace-scoped reading. When no directory is supplied, it reports OpenCode as unavailable rather than querying the plugin install directory; the other providers remain available. It caches successful values, rate-limits refreshes per provider/account (and per OpenCode workspace), preserves stale readings after failure and shows unavailable/authentication states without substituting local run counts. It does not generate prompts to refresh usage. History persists job status metadata only; prompts and responses are not written to the history file.

The local dashboard is the optional visual surface for Codex. Start it from this package with `npm run dashboard -- --directory <absolute-workspace-path>` to include OpenCode's workspace-scoped reading; without a directory, OpenCode is reported unavailable. It binds only to loopback, prints a one-time local URL and exits the token URL after establishing an HttpOnly local session. OpenCode Go and Google AI Pro usage formats can vary by CLI version; if their structured response lacks quota fields, the dashboard reports that honestly. The MCP server is built to `server/dist/index.mjs`, which bundles the runtime dependencies and includes the shared engine files inside the plugin package.

`start_pipeline_job` runs an explicitly selected planner, implementer and independent reviewer, then an allow-listed verifier. It creates a new `codex-bridge/<id>` Git branch and worktree from committed `HEAD`, leaves the source checkout and any uncommitted edits alone, permits one bounded verification retry, and preserves the worktree for owner inspection. Multiple pipeline jobs can run concurrently up to the bridge limit. It never merges or pushes. Cross-provider fallbacks make one attempt only for classified authentication, missing-CLI or rate-limit failures; other failures return directly for explicit owner review.

## Windows 11 installation

1. Install Node.js 20+. The committed MCP bundle runs without a local npm install. For development, run `npm ci`; after source changes run `npm run build` to regenerate the bundle, then `npm run check` to verify the bundle and tests.
2. Authenticate OpenCode and Antigravity through their own CLIs. To set up each Codex profile, open a separate PowerShell session for each account and run ` $env:CODEX_HOME="$env:USERPROFILE\.codex-profiles\pro-1"; codex login `, then repeat with `pro-2` and sign in to the other account. These are user-operated browser sign-ins; do not copy credentials between profiles.
3. Configure `BRIDGE_OPENCODE_BIN`, `BRIDGE_CODEX_BIN` or `BRIDGE_AGY_BIN` if Windows PATH does not expose a native executable.
4. From the cloned repository root, run `codex plugin marketplace add <absolute-path-to-opencode-go-mod>` and confirm it with `codex plugin marketplace list`, then install the `agent-subscription-bridge` entry. The package uses the official plugin manifest, skill and bundled MCP server mechanism. Verify discovery in the actual Codex build you use.
5. Run `bridge_status` and `bridge_usage` with the absolute workspace `directory`, then a read-only delegation against a disposable Git repository. To use `start_pipeline_job`, set `BRIDGE_ENABLE_WRITES=1` explicitly in the MCP server environment. To view quota readings in a browser, start `npm run dashboard -- --directory <absolute-workspace-path>` and open the one-time loopback link it prints.

The repository includes a marketplace example under `.agents/plugins/marketplace.json`. Actual package installation and authenticated provider results must be checked on the target machine.

Codex does not use Claude's custom sidebar APIs. Its supported visual fallback here is the local loopback dashboard, and its native integration uses Codex's plugin, skill and MCP interfaces.
